# Codex 原始条目元数据观测

这是定位 `item_` 来源的临时观测，不是历史修复。默认关闭；仅在目标 Happy
进程启动环境中设置 `HAPPY_CODEX_RAW_ITEM_DIAGNOSTICS_SESSION=<完整 Happy session ID>`。
`1`、原生 thread ID 或其他会话 ID 均不会开启。选择在 runtime 初始化时固定，
更换账号不重置计数；不要为启用它开启全局 DEBUG 或重启全部会话。

观测点是已有 `rawResponseItem/completed` 回调，沿用现有 client 身份校验，
不增加 RPC、不修改事件、历史、输入队列或恢复逻辑。它最多记录 16 条非 `item_`
样本和 128 条 `item_` 样本；普通样本不会耗尽后者的预算。达到上限后停止记录，
不新增队列或自动重启。诊断提取失败只关闭该 observer，写入失败只丢弃诊断。

只允许固定的类型/工具分类、ID 前缀/长度、短标识符的 SHA-256 关联摘要及
密文字段是否非空。没有正文、参数、密文值、动态字段名、认证数据或完整 ID。
关联摘要不是匿名化保证；仍按私有诊断数据处理。不超过 256 字符的标识符才计算摘要。

复用 `diagnosticTrace`：异步本地写入 `/private/tmp/xc-disposable/happy-diagnostic.*/`
下当前进程的版本化日志，标记为 `[CODEX_RAW_ITEM]`。该通道禁用远程发送、
单文件最多 2 MiB；容量与其他诊断共用，满额或清理后可能无记录，不能据此断言事件没发生。
由已有临时目录清理机制回收，不创建第二套保留策略。
注意：同一文件中的既有 `[USER_INPUT]` 等记录可能包含正文；本功能不改变那些记录。
不要分享整份诊断日志，需要交接时只提取本标记的记录并检查内容。

该记录最多证明 ID 到达 Happy 的 app-server 通知边界时的形态，不是 HTTP/WS 原始响应。
当前 fresh thread 已启用 experimentalRawEvents；resume 是否继续发事件须实测，
不能因缺少记录而改写真实历史、重放输入或创建替代业务线程。关闭需移除目标进程的开关，
下次启动生效；本改动不部署、不自动重启现有进程。
